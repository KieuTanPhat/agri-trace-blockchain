## Source and reproducible export

Nest controllers and existing DTO decorators are the source. `main.ts` and `openapi-export.ts` both call `createOpenApiDocument`; Swagger UI only displays that document. No schema is copied from UI or into Word. Explicit decorators are used, so no Swagger compiler plugin change to `nest-cli.json` is necessary.

From the repository root, using the Node/npm versions in `package.json`:

```sh
npm ci --no-audit --no-fund
npm run build --workspace blockchain/gateway
npm run prisma:generate --workspace apps/api
npm run api-contract:generate
npm run api-contract:check
node scripts/ci/api-contract-evidence.mjs
```

The exporter does not start an HTTP listener or connect to deployment databases. JSON is sorted, validated with Swagger Parser, checked for references, empty named schemas, operationId uniqueness, envelopes, required idempotency headers, security metadata and public projection exclusions. `--check` also compares committed JSON, checksum, operation index and generated Web types with a fresh export.

## Delivered contract

- `openapi.json`: 67 operations, OpenAPI 3.0, API version 2.1.0.
- `openapi.sha256`: checksum of LF-normalized JSON.
- `operations.json`: method/path/operationId handoff for AGT-011. Preserve IDs when moving/renaming controller methods; explicitly annotate a legacy ID when needed.
- `../../apps/web/src/lib/generated/api.d.ts`: generated by openapi-typescript, not edited by hand.
- CI artifact `openapi-<checkout SHA>-node-<Node version>`: JSON, checksum, operation index, types, `metadata.json` and `review.json`; retained 30 days. Metadata records actual checkout SHA, dirty state, API version, environment, Node/platform, run URL and schema digest. A PR checkout SHA may be a merge commit, not the PR head.

Changes include optional request nullability, calendar-date descriptions, registration request metadata (registration still returns 501), Catalog Bearer security, device-key security for the two device ingestion endpoints, and `x-roles` from existing role decorators. Idempotency is a command header, not an authentication scheme; it is trimmed, limited to 255 characters after trimming and may produce 409 for missing/invalid/conflicting keys. Existing runtime authorization still applies on replay.

Raw Prisma record Decimal fields serialize to strings; lot presenters explicitly convert quantities to numbers. Raw Date fields serialize as ISO date-time, while lot `expiryDate` is `YYYY-MM-DD` or null. Optional request nullability describes DTO validation; business rules can still reject a request with an error envelope. Nullable object references use an explicit null branch because nullable on an allOf wrapper alone does not admit null.

## Verification and remaining acceptance

`lot-projection.contract.spec.ts` exercises the real HTTP interceptor/filter, DTO validation and lot presenters with database service fixtures. It validates public/internal projections, nullable dashboard, raw Prisma Decimal/date serialization, and 400/404 errors using JSON Schema validation. Negative cases reject the wrong Decimal representation. Auth guards are overridden in this isolated test; it is not evidence of production RBAC acceptance.

`traceability-workflow.e2e-spec.ts` uses the production document factory and validates responses from its GET/POST helpers against that document. The follow-up review started Docker and provisioned an isolated PostgreSQL 16.15 container, applied all 14 migrations and passed all 91 e2e tests (including 38 workflow tests). The disposable container was removed after testing. CI has its own PostgreSQL service and runs API checks before contract export/upload.

Breaking-change review: set `CONTRACT_BASE_SHA` to a full baseline commit and run `node scripts/ci/api-contract-evidence.mjs`. CI supplies the PR/merge-group base or previous push SHA. `review.json` lists changed/removed existing operations and components, plus inherited path parameters and document-level security/servers/OpenAPI version changes. Object-key reordering is ignored. This is a conservative review aid, not a semantic breaking-change verdict or proof of reviewer approval. Dispatch without a baseline records `baseline-not-supplied` explicitly. Tuấn and Phát must assess compatibility and decide whether version 2.1.0 remains appropriate before acceptance.
